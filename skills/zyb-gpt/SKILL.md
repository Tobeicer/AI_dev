# 复杂项目对齐开发

在真正需要项目上下文和工程判断时，帮助 Codex 继承现场、沿正式实现推进，并避免隐蔽分叉与无关发散。

## 触发边界

仅在任务至少符合一项时使用：

- 接手陌生、长期演进或已有较多约束的代码库，需要先理解现状再开发。
- 功能、修复或重构涉及多个文件、调用链、接口、配置或消费者。
- 问题需要结合日志、测试、进程、数据或运行环境进行复现和诊断。
- 需求、文档、代码和实际行为之间存在需要判断的冲突或缺口。
- 用户显式调用 `$zyb-gpt`。

不要仅因为当前目录是 Git 仓库，或用户说了“继续”“执行”“确认”“验证”，就自动使用本技能。以下任务默认不触发：

- 单独执行 `git status`、`add`、`commit`、`push`、查看日志等确定性 Git 操作。
- 对明确目标进行简单的新建、删除、复制、移动或重命名。
- 修改一处文案、README 条目、配置值或进行纯格式调整。
- 按用户给出的固定入口运行命令或测试，且不需要进一步诊断。
- 普通问答、状态汇报、内容摘要和与项目开发无关的开放式讨论。

若简单任务在执行中暴露出跨模块影响、状态冲突或复杂故障，可从出现复杂性的那一轮开始使用本技能。

启用本技能不代表自动提高推理强度、扩大检查范围或增加流程；分析和验证成本仍应与当前任务风险成比例。

## 工作方式

### 建立最小有效基线

只读取足以避免跑偏的现场：项目级指令、直接相关的权威文档、正式实现与入口、关联测试，以及与问题有关的状态或运行证据。不要为了“理解完整”通读整个仓库或重复读取已经掌握的内容。

### 沿正式链路推进

- 优先复用和改进现有正式入口；现有实现确有缺陷时可以修复或重构。
- 不静默新增同功能的 `v2`、`new`、`rewrite`、临时旁路或平行工作流。
- 保留用户已有改动，区分正式实现、实验资产与临时产物。
- 发现文档、代码和运行行为冲突时，按用户最新指令、项目权威顺序和实际证据判断；会改变方向的冲突应保持可见。

### 直接执行并按风险验证

用户已经授权的范围内，完成必要现场确认后直接实施，不重复询问同一决定。验证应覆盖实际风险：局部修改做局部检查，跨模块变更再扩大回归；不要让文档、计划或测试仪式替代实现。

只有缺少会明显改变结果的选择、需要新的权限或外部责任、涉及重大难恢复操作，或安全替代方案已用尽时，才暂停请求用户决定。

### 准确交付

完成后说明实际修改的核心文件或系统、使用的正式入口、验证结果、外部状态变化和仍未完成事项。区分“已生成、已保存、已验证、已写入目标系统”等状态，不把中间结果称为最终完成。
